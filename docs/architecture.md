# System map

Read this when a task spans projects, agent configuration, infrastructure or external apps. The boundaries below were checked on 2026-11-12; use the linked sources for current implementation details.

| Part | Owns | Read or change here |
| --- | --- | --- |
| skills | Shared agent instructions, reusable skills and installer configuration | [Steering-file map](../README.md#home-repo-and-steering-files), [repo pointers](../config/repos.md), and each skill's `SKILL.md` |
| Each project repo | Its code, commands, architecture, decisions and GitHub issues | Its `AGENTS.md`, README and `docs/`; resolve the checkout through the repo pointers |
| T3 Code | Interactive sessions, worktrees and linked environments | The selected T3 project and environment; each affected repo keeps its own branch and worktree |
| proj | Agent status, GitHub mirrors, registered project docs, runner coordination and deployment visibility | [proj README](https://github.com/timblazing/proj/blob/main/README.md) and [architecture](https://github.com/timblazing/proj/blob/main/docs/architecture.md) |
| homelab | Infrastructure documentation and service context | The homelab checkout's README and relevant service documentation; verify deployed configuration before changing it |
| Executor | Interactive external-app access through connected accounts | MCP tools: search, describe, then call; account setup is on proj's MCP page |

## How the parts connect

`install.sh` makes skills and steering files available to Claude Code and Codex. T3 sessions load the installed instructions and the current repo's instructions. Cross-repo work starts in the skills T3 project, uses the repo map, and keeps changes in each owning repo. A T3 project does not require registration in proj.

proj reads GitHub state and registered repos' Markdown, receives agent activity, and presents results. Its MCP provides read-only access to those mirrors. It also acts as a paired T3 client; T3 owns execution of interactive sessions. Skills remains outside proj's project registry, so agents read this map through filesystem pointers or GitHub. The project Docs UI remains hidden.

Unattended Claude tasks run through GitHub Actions, normally on anton's single-use runners. proj coordinates those runners; each workflow installs skills before running. Unattended changes use branches and PRs, including in this repo. Interactive skills work follows the shared non-product repo policy. Codex remains available for interactive work and PR review; a Codex comment-to-task workflow on anton is still a separate follow-up. See [the execution decision](https://github.com/timblazing/proj/blob/main/docs/decisions/0024-agents-run-on-anton.md).

Executor supplies external context and actions to interactive sessions. It is a service gateway, not another agent runner. Follow the shared external-app confirmation rule for writes. Unattended runs do not use Executor. See [external-app setup](../README.md#external-apps) and [Executor hosting](https://github.com/timblazing/proj/blob/main/docs/decisions/0020-executor-on-raygun.md).

Deployment belongs to each product repo's workflow. For example, merging proj's default branch deploys proj; changing skills updates the installed agent setup through machine sync. Check the owning repo's release rules before integration. A successful local check is separate from CI, deployment and device acceptance.

## Choose the owner of a change

- A rule true across repos belongs in skills; a build command or domain rule belongs in its project.
- A change to agent setup generated by proj belongs in proj's setup template. Registered projects receive setup PRs; supporting repos outside the registry need an explicit refresh. Leave custom repo sections intact.
- A service connection or deployment question starts with homelab and the owning repo, then current host evidence. This map does not duplicate secrets or live configuration.
- Durable work belongs in the owning repo's GitHub issues. Shared knowledge belongs in Markdown with source links, not in a second backlog or a copied chat history.

Keep this map public-safe. Private knowledge stays in its existing private sources until a separate storage decision is made. Model, effort, theme and output style are machine-local Claude preferences that sync never overwrites; the README's [settings ownership](../README.md#settings-ownership) section lists which keys are shared.
